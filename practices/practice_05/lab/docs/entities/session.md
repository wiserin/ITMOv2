# Сессия (Session)

## Назначение

Session — серверное состояние аутентификации пользователя. В MVP одна сессия представлена одним JWT bearer-токеном. Access/refresh-пары и операции refresh отсутствуют. После MVP эта модель предположительно станет основой refresh-токена.

Связь с [`User`](user.md) — многие-к-одному. Ограничение на одну сессию пользователя не вводится. Схема хранения — [`sessions`](../database.dbml), процесс аутентификации — [`../auth.md`](../auth.md).

## Атрибуты

Доменная модель — `dataclass(slots=True)`; ORM-модель отделена и маппится в domain и обратно.

| Атрибут | Доменный тип | Назначение |
| --- | --- | --- |
| `id` | `UUID` | UUIDv4 сессии, создаваемый в domain; значение `jti` в JWT |
| `user_id` | `UUID` | Владелец сессии |
| `secret` | `str` | Индивидуальный случайный секрет сессии, передаваемый внутри JWT |
| `secret_hash` | `str` | Argon2id-хэш этого секрета с солью и параметрами алгоритма |
| `created_at` | `datetime` | Время создания |
| `last_used_at` | `datetime` | Время последней успешной аутентификации |
| `closed_at` | `datetime \| None` | Время закрытия; `None` означает отсутствие явного закрытия |
| `expires_at` | `datetime` | Текущий срок истечения из-за неактивности |

Все временные значения содержат часовой пояс; расчёты выполняются в UTC.

## Инварианты

1. Сессия принадлежит ровно одному существующему пользователю. `id`, владелец и `created_at` не меняются.
2. Секрет создаётся криптографически стойким генератором индивидуально для сессии (не менее 32 случайных байт с кодированием base64url). Он не является ключом подписи JWT.
3. В MVP сохраняются **и `secret`, и `secret_hash`**, как отдельные обязательные поля. Проверка предъявленного секрета выполняется через Argon2id verify, а не сравнением с открытым полем. Хэш должен соответствовать секрету; SQL-проверка непустых полей это соответствие не обеспечивает.
4. Секрет и его хэш не меняются при продлении сессии. Для нового секрета создаётся новая сессия.
5. При создании `last_used_at = created_at`, `closed_at = None`, `expires_at = created_at + timedelta(minutes=app_config.session_idle_timeout_minutes)`.
6. `app_config.session_idle_timeout_minutes` — положительное целое число минут. Проверяется при загрузке конфигурации. Конкретное значение пока не определено.
7. Сессия действительна только если `closed_at is None`, `now < expires_at` и владелец активен. При `now == expires_at` сессия уже истекла. Отсутствие `closed_at` само по себе не означает действительность.
8. При успешной аутентификации `last_used_at = now`, `expires_at = last_used_at + timedelta(minutes=app_config.session_idle_timeout_minutes)`. Используется актуальная конфигурация на момент операции. Уже сохранённый срок не пересчитывается до успешного использования.
9. `last_used_at` не уменьшается и не предшествует созданию; `expires_at > last_used_at`. У закрытой сессии `closed_at >= last_used_at`.
10. Закрытая или истёкшая сессия не продлевается и не открывается повторно. Для продолжения работы требуется новый вход.
11. Закрытие устанавливает `closed_at` один раз. Повторное закрытие не меняет исходное время; история сессии сохраняется.
12. Ошибка подписи JWT, неверный секрет, отсутствие сессии или неактивный пользователь не обновляют `last_used_at` и `expires_at`.
13. При физическом удалении пользователя сессии удаляются каскадно. Блокировка пользователя запрещает использование сессий без их физического удаления.
14. Секреты, хэши и целый JWT не включаются в логи или публичное представление сущности. Передача JWT клиенту при входе — отдельный контракт аутентификации.

## Изменение состояния

- **Создание** — после проверки текущего пароля активного пользователя.
- **Успешное использование** — проверка действительности и атомарное обновление времён без изменения JWT.
- **Закрытие** — установка `closed_at` при выходе; обновления времени использования после закрытия запрещены.
- **Истечение** — наступает автоматически при достижении `expires_at`, даже если фоновая обработка ещё не установила `closed_at`. Если истечение материализуется в БД, `closed_at` фиксирует время обработки и не продлевает сессию.

Проверка состояния, продление и закрытие должны сериализоваться блокировкой строки или условным атомарным обновлением. После потенциально долгой проверки Argon2id срок и состояние проверяются повторно по актуальному времени: конкурентный выход или наступившее истечение не должны быть отменены продлением. Дорогой verify не выполняется в event loop.
