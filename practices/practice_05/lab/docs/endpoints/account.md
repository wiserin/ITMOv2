# Account — текущий аккаунт и поиск пользователей

Префикс группы: `/v1/account`. Ответы — JSON. Аутентификация выполняется по автоматически отправляемой браузером cookie `session_token` (`Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`). Заголовок `Authorization` не заменяет cookie.

| Метод и путь | Назначение | Кто может пользоваться |
| --- | --- | --- |
| `GET /v1/account/me` | Получить свой текущий аккаунт | Любой активный аутентифицированный пользователь: user, moderator, admin |
| `GET /v1/account/find/{username_prefix}` | Найти аккаунты по префиксу username | Активные moderator и admin; admin наследует права moderator |

## GET /v1/account/me

Возвращает владельца текущей сессии из auth DI. Параметров и тела запроса нет. Получить чужой аккаунт подстановкой ID нельзя: источник данных — только аутентифицированный пользователь.

Ответ `200 OK` (`AccountResponse`):

```json
{
  "id": "899f2a44-9842-4d1a-b951-03bc78d1e6e9",
  "email": "root@example.com",
  "username": "root",
  "display_name": "root",
  "role": "admin",
  "is_active": true
}
```

`display_name` может быть `null`. Роль возвращается строкой (`user`, `moderator`, `admin`), хотя в application/domain и БД её код целочисленный. Пароли, хэши, JWT, секрет сессии и её срок не возвращаются. Заголовок ответа — `Cache-Control: no-store`.

Ошибки:

- `401` — cookie отсутствует, сессия недействительна/истекла либо владелец неактивен.
- `503` — хранилище недоступно; `400` — повреждённый сохранённый хэш секрета.

## GET /v1/account/find/{username_prefix}

Возвращает страницу совпадений по началу username. Например, `/v1/account/find/ani?limit=20&offset=0` предназначен для поиска `anime-fan`, `animemap` и других username с таким началом.

### Параметр пути

- `username_prefix` — обязательная строка длиной 1–100 символов после удаления пробелов по краям.
- Регистр сохраняется. Контракт репозитория — регистрозависимое буквальное сравнение префикса, не поиск подстроки.
- `%` и `_` — обычные символы префикса, не SQL wildcard. SQL-адаптер экранирует их при построении запроса.
- Специальные символы передаются с URL-кодированием. Тела запроса нет.

### Query-параметры пагинации

| Поле | По умолчанию | Допустимые значения |
| --- | --- | --- |
| `limit` | 20 | Целое число от 1 до 100 |
| `offset` | 0 | Целое число от 0 до 10 000 |

Параметры необязательны; пропущенное поле получает значение по умолчанию. `offset` задаёт число пропускаемых совпадений после сортировки, `limit` — максимальное число возвращаемых аккаунтов. Верхняя граница offset ограничивает глубину постраничного просмотра.

Query Request — непосредственно `PaginationRequest`, подключённый через `Annotated[PaginationRequest, Query()]`: других query-параметров в этой ручке нет. `username_prefix` остаётся в пути. Числовые строки преобразуются в int, дробные и нечисловые значения отклоняются. Неизвестные query-поля запрещены.

Ответ `200 OK` (`FindAccountsResponse`):

```json
{
  "accounts": [
    {
      "id": "dba67b3b-3ac2-4d73-a793-e45aa0c83447",
      "email": "anime-fan@example.com",
      "username": "anime-fan",
      "display_name": "Anime Fan",
      "role": "user",
      "is_active": true
    }
  ]
}
```

Если совпадений нет или offset находится за пределами найденных совпадений, возвращается `200` с `{"accounts": []}`, а не `404`. Username не уникален: несколько аккаунтов с одинаковым username должны сохраняться в выдаче и различаются по UUID. Перед применением offset/limit репозиторий сортирует результат по username, затем по ID. Ответ содержит только выбранную страницу; общее количество совпадений не рассчитывается.

Результат поиска содержит те же поля аккаунта, что и `/me`, без credentials и сессионных данных. Ответ имеет `Cache-Control: no-store`.

Ошибки:

- `401` — пользователь не аутентифицирован или неактивен.
- `403` — аутентифицированный пользователь не имеет роли moderator/admin. Проверка прав выполняется до обращения к репозиторию. Доменный тип — `PermissionException`, контекст операции передаётся в `details`.
- `400` — префикс пуст после trim или превышает 100 символов; limit/offset имеют неверный формат или выходят за границы; переданы неизвестные query-поля. Отсутствующий сегмент пути не соответствует маршруту.
- `400` также возвращается при повреждении сохранённого хэша секрета.
- `503` — PostgreSQL временно недоступен; ошибка поиска не маскируется под пустой список.

## Реализация и границы текущего этапа

- `/me` использует `AuthUseCaseDI` и `AccountResponse.from_dto(user)`.
- Для поиска `PaginationRequest.to_dto()` создаёт внутренний `PaginationDTO`; username_prefix передаётся отдельно из пути. DI возвращает конкретный `FindAccountsUseCase`, который задаёт `min_permission=UserRole.MODERATOR` через `super().__init__()`. Метод `find_accounts` сначала вызывает `authorize(requester)`, сравнивающий `access_level <= requester.role`, и только при успехе обращается к доменному `UserRepository` с limit/offset. Репозиторий возвращает страницу `UserEntity`, UseCase преобразует их в `UserDTO`, а presentation вызывает `FindAccountsResponse.from_dto()`.
- Поиск реализован через SQLAlchemyUserRepositoryAdapter: ORM-запрос выполняется асинхронно в общей бизнес-сессии запроса. AuthUseCase проверяет EdDSA JWT и Argon2id-секрет, перечитывает состояние под блокировками и фиксирует продление в отдельной auth-сессии до возврата пользователя. Продление сохраняется даже при последующем `403` или откате поиска.
- API-тесты подменяют auth UseCase и UserRepository, сохраняя реальную проверку прав FindAccountsUseCase и маппинг доменных сущностей.
- Интеграционный тест поиска подменяет аутентификацию и источник тестовой сессии. Отдельный тест auth проверяет полный цикл с настоящими криптографическими адаптерами, UseCase и PostgreSQL, включая сохранение продления при `403`. Подробности — в [документации репозиториев](../repositories.md).

Все собственные ошибки обрабатываются общим presentation mapper. Формат — `error/message/details`, описание — в [контракте ошибок](../errors.md). Поиск не создаёт собственный тип исключения для отказа в доступе.
