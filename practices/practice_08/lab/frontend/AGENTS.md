# Правила фронтенда

Применять вместе с `../agent-rules/`. Актуальное задание пользователя
разрешает редактирование существующего фронтенда. Оно заменяет старый
запрет на изменение существующих файлов из общего контекста.
Контракты API читать в `../docs/`; бэкенд не изменять.

## Обязательная библиотека UI

- Все визуальные компоненты интерфейса использовать из собственной
  библиотеки `src/UI`, через публичный экспорт `src/UI/index.ts`.
- Если нужного компонента нет, сначала реализовать его в
  `src/UI/components/`, экспортировать и документировать, затем
  использовать в интерфейсе. Один компонент — отдельный файл.
- Внутри библиотеки использовать прямые относительные импорты,
  чтобы не создавать циклы через общий экспорт.
- В страницах и `App.tsx` допустимы структурная HTML-разметка,
  заголовки, текст и композиция готовых компонентов. Не создавать
  там собственные кнопки, поля, карточки, модальные окна или другие
  повторные реализации элементов библиотеки.
- Цвета, отступы, размеры текста и скругления задавать токенами
  из `src/UI/styles/tokens.css`. Все CSS хранить в `src/UI/styles/`;
  подключать `index.css` один раз из `src/main.tsx`.
- Запросы API, маршрутизацию, права доступа и состояние сценариев
  держать в страницах, `App.tsx` и `api/`. UI получает данные и
  обработчики через типизированные props. Предметные компоненты
  могут использовать типы API и чистые проверки роли без запросов.
- Сохранять семантику HTML, доступные имена, управление клавиатурой,
  возврат фокуса, адаптивность и reduced motion.
- Изменения библиотеки отражать в `../docs/frontend/README.md`.
  Проверять сборку и затронутые браузерные сценарии; серверные
  контракты проверяются существующей командой `npm test`.

Основная документация: [docs/frontend](../docs/frontend/README.md).
