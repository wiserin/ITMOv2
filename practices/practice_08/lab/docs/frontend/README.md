# AnimeMap: текущее состояние фронтенда

Фронтенд находится в `frontend/`: React 19, TypeScript в строгом
режиме, сборка Vite, сервер Node.js 22+. Собственная библиотека UI
содержит визуальные компоненты и все стили приложения. Отдельной
публикации в npm и внешней библиотеки компонентов нет.

## Структура и ответственность

```text
frontend/
  AGENTS.md                 обязательные правила фронтенда
  src/
    UI/
      index.ts              публичные экспорты компонентов
      components/           один компонент на файл
      styles/
        index.css           точка подключения стилей
        tokens.css          цвета, отступы, типографика, радиусы
        base.css            сброс, HTML, фокус, базовый шрифт
        components.css      оформление компонентов
        layouts.css         композиция экранов и иллюстраций
        responsive.css      адаптивность и reduced motion
    api/client.ts           HTTP-клиент, типы, ошибки, RBAC helper
    pages/                  сценарии, запросы, состояние, композиция
    App.tsx                 маршрутизация и текущий аккаунт
    main.tsx                React root, однократный импорт CSS
  server/                   SPA, TLS, разрешённый API proxy
  tests/                    серверные и браузерные проверки
```

Прежние `src/components` и `src/styles/global.css` перенесены в UI.
Дублирующих реализаций по старым путям нет. Библиотека включает
нейтральные элементы и предметные компоненты AnimeMap; тип
`AccountResponse` пока общий с HTTP-клиентом. Компоненты не выполняют
сетевые запросы. Header использует чистую проверку `canModerate`.

## Каталог компонентов

| Экспорт | Назначение и основные props |
| --- | --- |

| `TextField` | Подписанное поле; `label`, необязательный `hint`, нативные input props, включая `name`, `required`, `autoComplete`, `value`, `onChange`. Вложенный label связывает подпись с полем. |
| `Card` | Семантическая секция с общим оформлением; HTML props секции, `className` для варианта композиции. |

| `Spinner` | Декоративный индикатор; текст и `role="status"` задаёт контейнер. Учитывает reduced motion. |
| `EmptyState` | Пустой результат или загрузка; `title`, пояснение в `children`, `loading`. |

| `Header` | Шапка и меню аккаунта; `account`; мышь, касание, клавиатура, Escape, закрытие снаружи; уведомление о заглушке выхода. |

## Использование и расширение

**Все визуальные компоненты используются из собственной библиотеки.**
Если компонента нет, сначала создать его в `UI/components`, добавить
публичный экспорт и документацию, затем использовать в интерфейсе.
Обязательное правило также закреплено в
[frontend/AGENTS.md](../../frontend/AGENTS.md).

Пример импорта из файла в `src/pages`:

```tsx
import { Button, Card, TextField } from '../UI';

<Card>
  <TextField label="Email" name="email" type="email" required />
  <Button variant="primary" type="submit">Войти</Button>
</Card>
```

Для отправки пример помещается внутрь формы с обработчиком страницы.
Нативные HTML-атрибуты сохраняются: валидация и `FormData` работают
через обычные `name`, `required`, `type`; `fieldset disabled`
блокирует поля и кнопку при выполнении запроса.

Страницы составляют UI, хранят состояние и вызывают API. Структурные
`main`, `section`, `div`, заголовки и текст допустимы вне библиотеки.
Собственные копии кнопок, полей и других готовых элементов запрещены.
Внутри UI импортировать соседние компоненты напрямую, снаружи — через
`UI/index.ts`.

`main.tsx` один раз импортирует `UI/styles/index.css`. Порядок:
шрифт → токены → база → компоненты → композиция → адаптивность.
Manrope загружается из Google Fonts; предусмотрен системный fallback.

Цвета именуются по назначению: `--color-primary`, `--color-error`,
`--color-surface`. Отступы — `--space-24`, размеры текста —
`--text-13`, радиусы — `--radius-7`, семейство — `--font-family`.
Существующие значения сохранены, включая небольшие различия
иллюстраций и отступов; шкала не округлялась при переносе.
Новые значения сначала добавлять в `tokens.css`, затем применять
через `var(...)`; не добавлять локальные палитры и inline-стили.
Размеры иллюстраций, media queries, проценты и сетки остаются в CSS.
Адаптивные границы: 1500, 900 и 650 px.

## Экраны и поведение

| Маршрут | Текущее поведение |
| --- | --- |
| `#/login`, `#/register` | Вход по email; регистрация без автоматического входа, затем подтверждение на форме входа. Также поддержаны прямые `/login`, `/register`. |
| `#/` | Заглушка карты, шапка и меню аккаунта. |
| `#/account` | Загрузка своего профиля, ошибка с повтором, ссылка назад. |
| `#/admin` | Для moderator/admin: поиск буквального префикса username с учётом регистра, debounce 300 мс, отмена устаревшего запроса, пагинация, карточка пользователя. |

При старте приложение получает `/v1/account/me`; без сессии
переводит на вход. Обычному пользователю прямой переход в админку
показывает отказ. `401` защищённых запросов возвращает к входу.
Ошибки поиска отличаются от пустой выдачи; доступ контролирует и API.
Выход остаётся заглушкой: уведомление не завершает сессию.
Поиск локаций, карта и избранное пока не реализованы.

API вызывается на том же origin через `/v1/`. Node proxy превращает
регистрационный `303` в `201`, не следуя redirect. Cookie остаётся
Secure/HttpOnly; токен не сохраняется в JS или localStorage.
Пароль отправляется без trim; email нормализуется перед отправкой.
Контракты: [auth](../endpoints/auth.md),
[account](../endpoints/account.md).

## Запуск и проверка

Из `frontend/` с установленными зависимостями:

```bash
npm run build
npm start
```

Открыть `http://localhost:3000`. API по умолчанию ожидается на
`http://localhost:8080`, переопределяется через `API_ORIGIN`.
После правок клиента повторить сборку. Docker, HTTPS и настройка
proxy описаны в [frontend/README.md](../../frontend/README.md).

```bash
npm run build
npm test
npm run test:e2e
```

Playwright использует Chromium и локальный сервер на порту 3100;
при необходимости установить браузер: `npx playwright install chromium`.
Браузерные проверки подменяют API. Они проверяют сценарии UI,
но не подтверждают интеграцию с работающим бэкендом.
